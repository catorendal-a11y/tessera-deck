# ESP32-S3 boards (experimental)

[Back to the README](../README.md)

Tessera is made for the ESP32-P4 board in [Install](INSTALL.md). This page is about a port to ESP32-S3 boards with an 800 x 480 screen, and to the Waveshare -7B with 1024 x 600. It is in the releases from 1.1.0, with one firmware package per board; the CrowPanel and the -7B came later. One tester has run the Waveshare -7 build on the board: the display, touch, keys, actions on the PC and the native USB link work. Another runs the CrowPanel build on a V1.5 board: the picture, the colours, touch and the brightness control work, and the status gauges show over its USB-to-UART link. A third runs the -7B build: the display, the colours, touch and the USB link work. Nobody has run the Sunton build yet.

## Boards

| Board | Id | Screen | Host link |
|---|---|---|---|
| Waveshare ESP32-S3-Touch-LCD-7 | `tessera-s3-ws7` | 800 x 480, GT911 touch | native USB |
| Waveshare ESP32-S3-Touch-LCD-7B | `tessera-s3-ws7b` | 1024 x 600, GT911 touch | native USB |
| Sunton / Guition ESP32-8048S070 | `tessera-s3-8048s070` | 800 x 480, GT911 touch | CH340 USB-to-UART bridge, 921600 baud |
| Elecrow CrowPanel Advance 7.0 ESP32-S3, V1.3 to V1.5 | `tessera-s3-crowpanel7` | 800 x 480, GT911 touch | CH340K USB-to-UART bridge, 921600 baud |

All of them have 16 MB flash and 8 MB octal PSRAM. Other S3 boards with a 7 inch RGB screen need their own pin and timing entry in `boards/tessera_s3_board/tessera_s3_board.c`.

The Waveshare -7 panel runs at a 12 MHz pixel clock (29 Hz). Waveshare's demos use 16 MHz (39 Hz); on this board that has made the picture jump while PSRAM was busy. If you try 16, change `pclk_hz` in `tessera_s3_board.c` and report what you see.

The screen layout is scaled to the display size when the firmware starts, so the same UI code serves 1024 x 600 and 800 x 480. Key icons stay 72 px. The key grid is still 6 x 3. The panel reports its size and its image cache (2 MiB on the S3 boards, 8 MiB on the P4) in `get_info`, and the host trims what it sends to fit.

## Build

You need ESP-IDF 6.1 with the `xtensa-esp-elf` toolchain installed (`install.ps1 esp32s3`, or `idf_tools.py install xtensa-esp-elf`). From the repository root, once per board:

```
idf.py -B build/tessera-s3-ws7 -DSDKCONFIG=build/tessera-s3-ws7/sdkconfig -DIDF_TARGET=esp32s3 -DSDKCONFIG_DEFAULTS="sdkconfig.defaults;boards/tessera-s3-ws7.defaults" build
idf.py -B build/tessera-s3-ws7b -DSDKCONFIG=build/tessera-s3-ws7b/sdkconfig -DIDF_TARGET=esp32s3 -DSDKCONFIG_DEFAULTS="sdkconfig.defaults;boards/tessera-s3-ws7b.defaults" build
idf.py -B build/tessera-s3-8048s070 -DSDKCONFIG=build/tessera-s3-8048s070/sdkconfig -DIDF_TARGET=esp32s3 -DSDKCONFIG_DEFAULTS="sdkconfig.defaults;boards/tessera-s3-8048s070.defaults" build
idf.py -B build/tessera-s3-crowpanel7 -DSDKCONFIG=build/tessera-s3-crowpanel7/sdkconfig -DIDF_TARGET=esp32s3 -DSDKCONFIG_DEFAULTS="sdkconfig.defaults;boards/tessera-s3-crowpanel7.defaults" build
```

A S3 build in the repository removes the P4-only components from `managed_components`. The next P4 build downloads them again.

To make the package the host installs:

```
python tools/package_firmware.py build/tessera-s3-ws7 dist --board tessera-s3-ws7
```

The file is `dist/tessera-firmware-tessera-s3-ws7-<version>.zip`. The GUITION P4 package keeps its name, `tessera-firmware-<version>.zip`.

CI builds every S3 board on every push. The release workflow packages them next to the P4 firmware.

## Install

Open **Panel → Panel firmware and updates …**, choose your board in the list (the S3 boards have the same chip, so the dialog cannot tell them apart) and run *Full install (new or blank panel)*. The host refuses a package for another board than the one that is connected, and an app that does not fit its flash slot.

On the Sunton board and the CrowPanel the host opens the CH340 port with DTR and RTS low, because those lines are wired to the reset and boot pins. If the board resets when the host connects, report it.

## Not tested on hardware

The Sunton build has not run on a board, and the Waveshare -7, Waveshare -7B and CrowPanel builds have one test report each. Apart from that, the build is checked by compiling, by the host tests and by the native render of the screens at 800 x 480 and 1024 x 600. Post what you find in the [S3 test reports](https://github.com/catorendal-a11y/tessera-deck/discussions/29) discussion. Open points:

- Draw speed. The S3 has one fast path to PSRAM that the screen refresh shares with the code, since the code runs from PSRAM.
- Flicker or a drifting picture while the screen refreshes and flash or PSRAM is busy. The settings that should prevent it (bounce buffer, ISR in IRAM, restart in vsync) are copied from vendor examples. The Waveshare board was stable at 12 MHz.
- Touch on the Sunton board: the GT911 address (0x5D, with 0x14 as fallback) and the coordinate mapping. On the Waveshare board touch works.
- The backlight. The Waveshare -7 switches it on and off through its expander, so there is no dimming. The Sunton board uses PWM on GPIO2.
- The Sunton colour order. Two board revisions are known to differ. If red and blue are swapped, the first and last five data pins in `tessera_s3_board.c` have to be swapped.
- Updating over the air while the screen runs, and UART speed during it. At 921600 baud a 2 MB image should take about a minute.
- On the Waveshare board one image upload was not acknowledged right after the host connected. The host reconnected and it has not happened again; the cause is not known.
- The CrowPanel build comes from Elecrow's factory code and the V1.3 schematic. It runs on a tester's V1.5 board from 1.2.6 on; V1.3 and V1.4 have not been tried. The pixel clock is 12 MHz, where Elecrow's own examples use 16 to 20 MHz; the tester finds the panel at its best at 12. The clock edge is the one Elecrow's IDF example uses (`pclk_active_neg`). If the picture shimmers or has wrong colours on another hardware version, that edge and the clock are the first things to change in `tessera_s3_board.c`. Touch needs the board's helper chip at I2C address 0x30: the firmware sends it Elecrow's command 250, which takes the touch controller out of reset.
- The CrowPanel backlight is a command to the STC8H1K28 at I2C 0x30, in the V1.3 to V1.5 form (0 is full, 245 off). V1.0 and V1.2 boards take other commands, so the screen may stay dark or stay at one brightness on them.
- The Waveshare -7B is a different board from the -7: 1024 x 600, and an IO extension chip at I2C 0x24 that takes register writes (0x02 directions, 0x03 outputs) instead of the CH422G's 0x24/0x38 commands. Pins and porches come from Waveshare's 7B examples; the pixel clock is 21 MHz, where Waveshare uses 30. The backlight is on/off through EXIO2.
- PSRAM headroom. Code and read-only data are copied to PSRAM, and the two frame buffers (1.5 MB, about 2.5 MB on the -7B) and the image cache come on top.
